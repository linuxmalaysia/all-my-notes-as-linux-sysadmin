Sovereign Markdown Palace (Web)

DSOM Policy Adopter Skill

Purpose: To seamlessly ingest external architectural or governance documents and integrate them into the DSOM repository strictly adhering to the Triple-Ledger Synchronization Mandate and Core Rules.

Prerequisites

  • The user has provided an absolute path to a document (e.g., PDF or Markdown).
  • If the document is a PDF, the AI should use the iew_file or pdf-text-extractor tool to read the contents first.

Execution Workflow

  1. Ingest & Extract
  2. Read the provided document in its entirety.

  3. Extract the core architectural principles, rules, and actionable constraints that apply to the DSOM ecosystem.

  4. Draft Governance Document

  5. Create a dedicated, highly-structured Markdown file in the docs/governance/ directory.
  6. The file must contain OKF v0.1 YAML frontmatter (with okf_version, ype: documentation, itle, and imestamp).

  7. Format the document strictly following the Generative Engine Optimization (GEO) standard: Authoritative tone, verifiable statistics/quotes, H2 user-centric headings, and 200-400 word chunks.

  8. Core Engine Injection (AGENTS.md)

  9. Distill the most critical, actionable constraints from the new policy.

  10. Inject these constraints directly as a new numbered Core Rule into .agents/AGENTS.md. Be extremely precise; do not bloat the file.

  11. Triple-Ledger Synchronization

  12. README.md: Add a link to the new docs/governance/ file in the "Key Documents" table with a short emoji-prefixed description.
  13. CHANGELOG.md: Add an entry under ## [Unreleased] describing the new governance policy and rule addition.

  14. HISTORY.md: Append a new entry to the universal ledger detailing the architectural integration and the exact files modified.

  15. Defensive GitOps (Commit & Push)

  16. Run git pull --rebase origin main to ensure sync.
  17. Add all changed files: git add docs/governance/... .agents/AGENTS.md README.md CHANGELOG.md HISTORY.md
  18. Commit with an atomic, conventional commit message (e.g., docs(governance): adopt [Policy Name]).

  19. Push to all active remotes (e.g., GitHub and GitLab).

  20. Closure & Walkthrough

  21. Report the successful adoption to the user, highlighting the exact architectural changes made.
